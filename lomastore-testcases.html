로마스토어 E2E 테스트케이스 29개: 절차와 기대 결과

무엇을 누르고, 무엇이 맞아야 통과일까. 실행 가능한 29개 케이스를 독자가 읽을 수 있는 검증 명세로 정리했어.

Taeik2026-09-22코드 7fcdc45 기준
29전체 테스트케이스
11예약 smoke
18수동 regression

테스트케이스는 행동과 성공 판정을 함께 적어야 해. 로마스토어의 비회원 탐색부터 장바구니, 주문서 진입까지 현재 자동화가 검사하는 29개를 실행 코드에 맞춰 정리했어. 이 글은 2026년 9월 21일 main에 반영한 코드의 명세 스냅샷이야.

작성 기준

게시일은 2026-09-22, 구현 기준은 7fcdc45야. 아래 결과는 9월 21일 실행 기록이며 오늘 새로 실행한 결과가 아니야. 전체 케이스는 active, enabled=true이고 P1은 smoke 11개, P2는 regression 18개야.

범위와 공통 사전조건

  • 각 케이스는 새 브라우저 컨텍스트의 비회원 세션에서 시작해. 앞 케이스의 장바구니나 로그인 상태를 이어받지 않아.
  • 장바구니와 주문서 케이스는 대표 상품 1개를 직접 담고 완료 안내를 확인해. 대표 상품은 비회원 접근이 가능하고 재고가 있어야 해.
  • 가격은 고정 숫자 대신 그 실행에서 읽은 기준 상품 금액과 비교해. 애니메이션 숫자는 숨겨진 이전 숫자를 제외하고 현재 표시값을 읽어.
  • 주문자와 수령자 입력에는 테스트 전용 값을 사용해. 실고객 데이터는 필요하지 않아.
  • 최종 결제 버튼은 노출까지만 확인해. 결제, 주문 생성, 실제 주문 조회 성공은 이 29개에 포함되지 않아.

같은 준비, 다른 성공 판정

상품 담기, 장바구니 확인, 주문서 요약은 공통 함수로 재사용해. PRODUCT-003은 담기 결과와 비우기 버튼을, CART-001은 장바구니 표시와 수량 조절 진입점을 확인해. 준비와 일부 판정은 겹치지만 기존 ID를 유지한 현재 구현을 그대로 기록했어.

수량은 1 → 2 → 1 양방향으로 확인하고 금액은 기준 단가 × 수량으로 판정해. 정렬은 URL 변화만 확인하지 않고 화면 판매가의 순서까지 비교해. 주문서 상품 합계에는 주소, 배송비, 할인 적용 이후의 최종 결제 금액 검증을 포함하지 않아.

main smoke 실행 기록에서 해당 커밋과 결과를 확인할 수 있어. 저장소 접근 권한이 필요할 수 있어. 전체 실행과 smoke는 범위가 달라서 성공률을 직접 비교하지 않아.

  • SEARCH-002, STORE-002: 표시 판매가가 선택한 정렬 방향과 일치하지 않았어. 정렬 기준의 정책과 서비스 구현을 확인할 과제로 남겼고 검증을 약화하거나 skip하지 않았어.

  • 추가할 범위: 주문서 필수값과 형식 오류, 주소 선택과 배송비, 품절과 최대 수량, 실제 결제와 주문 정합성, 주문조회 성공과 실패는 별도 설계가 필요해. 현재 29개가 검증했다고 주장하지 않아.
